## 2025-05-15 - [React Rendering & Resource Optimization]
**Learning:** The application's custom state-based routing system relies on passing a `setPage` callback from the root `App.tsx` down to almost every major component. Because this callback was not stabilized with `useCallback`, any state change in `AppContent` (like `lastOrderId`) triggered a recreation of `setPage`, causing a cascade of unnecessary re-renders across the entire component tree. Additionally, `HomePage.tsx` performed O(N log N) sorting operations on every render, which becomes a bottleneck as the product catalog grows.
**Action:** Always stabilize top-level navigation and state-setter callbacks with `useCallback` when using custom routing. Memoize derived data that involves sorting or filtering of large datasets using `useMemo`. Utilize native `loading="lazy"` for product cards to reduce initial main-thread blocking and memory usage for off-screen assets.
